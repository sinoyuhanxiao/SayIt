# 语音问答（开发分支）

语音问答默认关闭，不改变原有按住说话、免提、AI 整理和选区编辑的设置。

## 使用

1. 在「设置 → 语音问 AI」开启开关。
2. 可以先在原应用里选中一段文字，也可以不选。
3. Windows 按一次左 `Alt + Space` 开始提问，之后单按左 `Alt` 结束录音并提交。`Esc` 放弃本次提问。启动组合键那次 Alt 的松开或长按重复不会结束录音；普通语音输入不启用该规则。如果左 Alt 已绑定原有录音功能，原绑定优先。
4. 独立窗口显示识别出的问题和 AI 回答。可以展开引用内容、复制回答。
5. 问答窗口开着时，按 `Alt + Space` 或点「语音追问」继续当前话题，保留最初的选区及此前成功的问答，不要求问答窗口在前台。关闭问答窗口后，再按快捷键开始新对话、重新读取选区。
6. 底部文字栏也可以追问：Enter 发送，Shift+Enter 换行，中文输入法选词时 Enter 不发送。文字提问需要在 AI 设置中配置自定义服务，始终使用该服务；公共体验服务器目前没有纯文字问答接口。未配置时明确提示，可以改用语音追问。

macOS 默认组合键为 `Control + Option + Space`。第一版以 Windows 为主要验证目标。

## Windows 开发入口（无需安装包）

打开桌面或开始菜单的 `SayIt Ask Dev`。入口运行 `scripts/windows/start-ask-dev.ps1`：

- 前端直接读取 WSL 仓库源码，通过本机 1430 端口加载，保存后自动刷新整个页面，重新初始化录音器及事件监听。
- 原生 Rust 代码由后台监视脚本同步到独立 Windows 构建目录，Tauri 自动编译并重启。首次需要准备编译缓存，之后不生成安装包。
- 开发版与 `SayIt Ask Test` 共用独立测试配置 `com.sayit.asktest`，退出测试版后再使用开发版。原版 `com.sayit.app` 不受影响；开发版关闭自动更新和开机启动。
- 修改代码会刷新或重启应用，正在录制的内容及临时对话可能重置。只在确认功能满意后打包安装程序。
- 原生日志在 `%LOCALAPPDATA%\SayItDevTools\ask-dev-live.log`，源码同步日志在 `ask-native-watch.log`。

## 独立 Windows 测试包

`scripts/windows/stage-ask-test.ps1` 把当前源码复制到独立的 Windows 构建目录，再由 `build-ask-test.cmd` 构建 NSIS 安装包。只在构建副本中设置：

- 程序名称为 `SayIt Ask Test`，可执行文件为 `sayit-ask-test.exe`，独立标识及数据目录为 `com.sayit.asktest`。安装器按独立进程名称检查运行状态，避免影响原版进程。
- 关闭开机启动、自动更新和旧版数据迁移，不读取或改写原版 `com.sayit.app` 的配置及历史。
- 测试包默认开启语音问答；普通 `dev` 源码构建仍默认关闭。
- 保留本地语音引擎的 CPU / Vulkan 后端。测试包降低 Rust 发布优化以缩短首次构建时间，本地 C++ 识别引擎保持优化构建。

试用时先退出原版（包括托盘进程），再打开 `SayIt Ask Test`，避免两套程序同时监听录音快捷键。退出测试版后可重新打开原版，不需要卸载原版。

提问时使用原有录音状态提示；处理时按 Esc，或在问答窗口点取消/关闭，可以取消本次请求。已取消、失败或超时的结果不会插入原应用。回答完成后，原有录音快捷键继续用于普通语音输入。

## 模型与数据

- 复用当前语音引擎和当前 AI 服务。服务器模式可沿用服务器的 AI；本地/云 API 模式需要已配置的 AI 服务，例如云端模型或本地 Ollama。
- 问答不受普通「AI 整理」开关和短语音整理门槛影响，也不会修改这些设置。
- 只引用触发提问时成功读取的选中文字，不发送光标前后的段落。使用远程服务时，录音和/或选中文字会交给相应的识别、AI 服务处理。
- 本次问答不写入普通口述历史，也不保存录音。关闭窗口后内容可能暂留在进程内存，下一次提问会替换它；退出应用后消失。
- 当前窗口保留本轮问答；模型使用最近最多 8 轮成功的问答，历史上下文总计不超过约 2,800 字符，较长的问题/回答会截断。失败或取消的问答不作为下一次的参考。没有内置联网检索。
- 没有持久化的问答历史列表，退出程序后不会保留。原有口述历史保持独立。

## 兼容性

- Windows 的 `Alt + Space` 原本用于窗口菜单，PowerToys Run 也可能使用它。可以在设置里改为其他组合，或清空以禁用。
- 原有 SayIt 快捷键优先注册；新快捷键冲突时，新功能报告冲突，保留原绑定。
- 通过系统辅助功能读取选区。网页、PDF、编辑器是否支持取决于其辅助功能实现；未读到选区时窗口会明确提示，并按独立问题处理。
- Windows 新提问在辅助功能读不到选区时，会在原窗口尝试复制选区并恢复原剪贴板；等待启动快捷键松开后才执行。Windows Terminal 使用 Ctrl+Shift+C，不发送可能中断终端命令的 Ctrl+C。密码框、程序自身窗口和未选中也会整行复制的部分代码编辑器不走此回退。普通口述及连续追问不启用复制回退。
- 超过 6,000 字符的选区不发送，窗口会提示缩短选区后重新提问。
- 公共体验服务器的额度与可用性由运营者控制，不保证无限免费问答。AI 未执行或失败时显示错误，不会把原问题当成回答。

- `npm test -- --reporter=dot`：51 个测试文件、648 项测试通过，包括原有口述流程、连续语音/文字问答、保留选区、取消后迟到结果、左 Alt 停止事件隔离及快捷键例外场景。
- 左 Alt 按键状态机的 Windows Rust 专项测试通过：初次启动组合键及其重复/松开不结束录音；新按下仅触发一次；非问答期间放行；原有绑定优先；旧的 Alt+Space 结束操作不插入多余空格。
- 开发版原生验证：用独立测试窗口模拟辅助功能不能读取的选区，确认复制回退读取成功、无选区时不复用旧剪贴板，以及原剪贴板文字恢复。未调用 AI 或麦克风。
- 自动刷新验证：保存前端源码后原生 WebView 自动刷新；原生源码同步后日志显示自动重编译，并确认开发进程已自动重启。
- `npm run build`、`npm run i18n:check`、`git diff --check`：通过。
- 浏览器检查：完成、等待、报错三种状态；引用内容展开；复制按钮状态；小尺寸窗口布局通过。

- 完整 Windows 原生构建及独立 NSIS 安装通过，保留 CPU / Vulkan 引擎。已安装测试版，原版程序文件哈希与运行进程保持不变；原版数据库另有一致性备份。
